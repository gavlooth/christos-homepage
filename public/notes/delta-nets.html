Δ-Nets: Local Graph Rewriting for Shared λ-Reduction

1. Lambda reduction and the cost of substitution

The untyped λ-calculus is a formal language for functions. Its terms are generated by the grammar

\[ t ::= x \mid \lambda x.t \mid t\,u. \]

There are three cases.

  • \(x\) is a variable.
  • \(\lambda x.t\) is an abstraction. It has parameter \(x\) and body \(t\).
  • \(t\,u\) is an application. It applies the function term \(t\) to the argument term \(u\).

Application associates to the left. Thus \(t\,u\,v\) means \((t\,u)\,v\). Abstraction extends as far to the right as possible unless parentheses stop it. Thus \(\lambda x.t\,u\) means \(\lambda x.(t\,u)\).

A variable occurrence is not the same thing as a variable name. The term

\[ x\,x \]

contains two occurrences of the same name \(x\). This distinction matters because λ-reduction substitutes for occurrences, not merely for names.

An occurrence of \(x\) is bound if it lies inside the scope of a surrounding abstraction \(\lambda x\) that owns it. An occurrence is free if no such surrounding abstraction owns it. For example, in

\[ \lambda x.(x\,y), \]

the occurrence of \(x\) is bound by the displayed abstraction, while the occurrence of \(y\) is free.

The fundamental reduction rule is β-reduction:

\[ (\lambda x.t)\,u \;\longrightarrow_\beta\; t[x:=u]. \]

The expression \((\lambda x.t)\,u\) is a β-redex. It is a reducible expression in which an abstraction is applied to an argument. The term \(t[x:=u]\) denotes capture-avoiding substitution: replace the occurrences of \(x\) in \(t\) that are bound by the displayed abstraction, and do not change which binders own which variables.

Capture avoidance is essential. If \(u\) contains a free variable \(y\), and substitution places \(u\) under a binder \(\lambda y\), then that free \(y\) must not become bound accidentally. Bound variables may be renamed before substitution. Such renaming is called α-conversion. For example, before substituting \(y\) for \(x\) in \(\lambda y.x\), one may rename the bound \(y\):

\[ (\lambda y.x)[x:=y] \equiv_\alpha (\lambda z.x)[x:=y] = \lambda z.y. \]

Without the renaming, the incorrect result would be \(\lambda y.y\), where the free \(y\) inserted by substitution has been captured.

A term is in normal form when it contains no β-redex. A term is normalizing if some sequence of β-reductions reaches a normal form.

The rule

\[ (\lambda x.t)\,u \;\longrightarrow_\beta\; t[x:=u] \]

is compact. It is not operationally neutral. It hides two different phenomena:

  1. the argument may be discarded;
  2. the argument may be duplicated.

These phenomena are the starting point for Δ-Nets.

1.1 Erasure: the argument may not be needed

Suppose \(x\) does not occur in \(t\). Then substitution has no occurrence to replace, and the β-step is

\[ (\lambda x.t)\,u \;\longrightarrow_\beta\; t. \]

The argument \(u\) disappears.

For example,

\[ (\lambda x.y)\;((\lambda z.z)\,w) \;\longrightarrow_\beta\; y. \]

The subterm

\[ (\lambda z.z)\,w \]

is itself a β-redex. If it is reduced first, the computation is

\[ (\lambda x.y)\;((\lambda z.z)\,w) \;\longrightarrow_\beta\; (\lambda x.y)\;w \;\longrightarrow_\beta\; y. \]

The first step was unnecessary for the final result. The outer abstraction ignores its argument, so any work performed inside the argument is discarded.

This is the erasure problem. It is not a logical problem. The λ-calculus equational theory is unchanged. It is an operational problem: an evaluator may spend time reducing a term that later has no consumer.

A reduction strategy can avoid some erasure waste. The normal-order strategy reduces the leftmost outermost redex first. In the example above, it reduces the outer application before entering the argument. Thus it immediately obtains \(y\). This is one reason normal order is important.

But erasure is only one side of the problem.

1.2 Duplication: the argument may be needed more than once

Suppose \(x\) occurs several times in \(t\). Then naïve substitution copies the argument:

\[ (\lambda x.x\,x)\,u \;\longrightarrow_\beta\; u\,u. \]

If \(u\) contains a redex, each syntactic copy may reproduce the same work. Let

\[ u = (\lambda z.z)\,w. \]

Then

\[ (\lambda x.x\,x)\bigl((\lambda z.z)\,w\bigr) \;\longrightarrow_\beta\; \bigl((\lambda z.z)\,w\bigr) \bigl((\lambda z.z)\,w\bigr). \]

The redex \((\lambda z.z)\,w\) now occurs twice. Reducing both copies performs the same computation twice.

The desired operational behavior is different:

  1. represent the multiple uses explicitly as sharing;
  2. reduce the shared computation once;
  3. let all consumers observe the resulting graph.

The point is not that the λ-calculus should stop duplicating in its mathematical definition. The point is that an implementation need not represent substitution as textual copying. It may represent one argument graph with several consumers.

A central motivation for Δ-Nets is therefore:

Avoid evaluating computation that will later be erased, and avoid recomputing necessary work merely because it has multiple consumers.

1.3 Reduction order is not enough

A reduction order is a rule for choosing which redex to reduce next. Normal order is one such rule. It chooses an outer redex before a redex contained inside it, and among outer redexes chooses the leftmost one.

For erasure, this helps. In

\[ (\lambda x.y)\;((\lambda z.z)\,w), \]

the argument is not reduced before the outer application erases it.

Duplication is harder. Once a β-step performs textual substitution, several copies of the same argument may exist as independent syntax. A later strategy can no longer know that these copies originated from one computation unless the representation remembers that fact.

The optimal-reduction tradition studies this issue. There are terms for which no ordinary sequential order of β-reductions avoids every duplicated reduction. The representation itself must expose sharing.

A syntax tree is not enough. A graph can do more.

2. From syntax trees to interaction nets

A syntax tree gives each occurrence its own branch. If an expression is used twice, a tree naturally presents two copies. A graph can instead let two consumers point to one connected subgraph.

Tree-like duplication:              Shared graph:

use₁ ── argument₁                  use₁ ─┐
use₂ ── argument₂                          ├── shared argument
                                           use₂ ─┘

The two drawings describe different representations. They need not describe different mathematical λ-terms. The shared graph records an operational fact: the two uses depend on the same computation.

A graph rewriting system computes by replacing a matched subgraph with another subgraph. The replacement is performed according to a rule. The rule must also specify how the surrounding wires are reconnected.

An interaction net is a graph rewriting system with a severe locality restriction. Its nodes are called agents.

An agent is a small graph node equipped with ports. A port is a connection socket. Each agent has exactly one distinguished port, its principal port. The remaining ports, if any, are auxiliary ports.

Two agents connected at their principal ports form an active pair. An interaction rule applies only to an active pair. The rule may remove agents, create agents, and reconnect the wires incident to the active pair. It may not inspect an arbitrary distant part of the net.

This local discipline has an important consequence.

An agent has only one principal port, so it cannot belong to two distinct active pairs simultaneously.

Indeed, to belong to an active pair an agent must use its principal port. Since it has only one principal port, that port can be connected to at most one other principal port. Thus two distinct active pairs share no agent.

This is the structural reason independent local interactions commute.

2.1 One interaction step

An interaction step is one application of one interaction rule to one active pair. It is a local computation. The step has as input:

  1. the two agents in the active pair;
  2. their ports;
  3. the wires immediately incident to those ports;
  4. the labels or metadata needed by the two agents.

It does not have as input the whole net.

This locality is not merely an implementation preference. It is part of the mathematical form of interaction nets. It is what allows parallel local rewriting to be controlled.

2.2 Perfect confluence

Suppose a net \(N\) has two possible one-step interactions:

\[ N \longrightarrow N_1, \qquad N \longrightarrow N_2. \]

The interaction-net core is said here to have the one-step diamond property when there exists \(M\) such that:

\[ N_1 \longrightarrow M, \qquad N_2 \longrightarrow M. \]

Every arrow in this diagram is exactly one local interaction.

        N
      /   \
    N₁     N₂
      \   /
        M

The property is called perfect confluence. It says that two competing one-step choices can be reconciled immediately. If one active pair is reduced first, and another independent active pair is reduced second, the result is the same as reducing them in the opposite order.

In symbols, the local commutation principle is

\[ \text{left then right} = \text{right then left}. \]

The proof idea is simple. Distinct active pairs share no agent. Each rule rewrites only its own active pair and reconnects only the wires incident to that pair. Hence reducing one pair cannot consume an agent needed by the other pair. The second rule remains applicable after the first. Since the two rewrites act on disjoint local neighborhoods, the final wiring is the same.

There are two qualifications.

First, perfect confluence is a property of the local interaction core. It does not by itself describe global cleanup procedures that inspect reachability or restore canonical form.

Second, perfect confluence is not termination. A system may have commuting local choices and still admit infinite reduction sequences. Agreement between choices does not imply that all choices end.

Thus the relevant assertion has a conditional form: when normalization occurs in the interaction core, normalizing orders agree on the result; in the stated Δ-Net core setting, they also agree on the number of core interactions.

2.3 Sharing scopes and bookkeeping

Optimal graph reduction must know when two pieces of structure belong to the same sharing context. Older interaction-net approaches often tracked sharing scopes with indexed fan agents and additional delimiter agents. Delimiters mark boundaries of duplication contexts. They also interact with other agents. In some systems, delimiter interactions can become numerous, and indices can grow without a fixed bound.

Δ-Nets move this bookkeeping into one kind of variable-arity agent: the replicator. A replicator carries an integer level and an integer delta on each auxiliary port. These numbers encode relative sharing-context information locally.

This is the main design distinction. Scope-sensitive sharing information is not represented by a separate family of delimiter agents. It is stored on the sharing agent itself.

3. The three agents

A Δ-Net core uses three kinds of agents.

Agent Auxiliary ports Role
Fan \(F\) 2 Application and abstraction structure
Eraser \(E\) 0 Explicit non-use / disposal
Replicator \(R\) Any natural number Explicit sharing and sharing-context bookkeeping

The diagrams conventionally distinguish them as follows:

  • a fan is a triangle;
  • an eraser has only its principal port;
  • a replicator is a variable-arity node, often drawn as a trapezoid;
  • rectangles in explanatory diagrams are endpoints or subnet labels, not agents.

A port has an identity independent of where it is drawn. This is important. A diagram may rotate a node. After rotation, a port may appear on the left rather than on the right. The port is still the same indexed port.

3.1 Fans

A fan \(F\) has exactly two auxiliary ports. The two auxiliary ports are ordered. Call them auxiliary port \(1\) and auxiliary port \(2\).

A fan is used for λ-term structure. In a rooted net, orientation determines whether a fan represents an application or an abstraction.

An application fan has:

  • principal port: the function connection;
  • first auxiliary port: the result or parent connection;
  • second auxiliary port: the argument connection.

An abstraction fan has:

  • principal port: its parent connection;
  • first auxiliary port: its body;
  • second auxiliary port: its bound-variable connection.

Thus the same triangular agent can represent either syntactic constructor. The distinction is not the shape of the triangle alone. It is determined by the direction of its wires relative to the root.

For a β-redex, an application fan and an abstraction fan meet at their principal ports. Their interaction is fan annihilation. This is the graph form of β-reduction.

3.2 Erasers

An eraser \(E\) has no auxiliary ports. It represents explicit non-use.

In λ-syntax, a binder may ignore its argument:

\[ \lambda x.y. \]

When this abstraction is applied, the supplied argument is discarded. In a Δ-Net subsystem that supports erasure, the non-use of \(x\) is represented by placing an eraser at the bound-variable connection of the abstraction.

Since an eraser has no auxiliary ports, it cannot carry continuation through an agent it meets. If \(E\) meets a distinct agent, the encountered agent is deleted and erasers continue through its auxiliary branches. For a two-port fan, two erasers continue. For an \(n\)-port replicator, \(n\) erasers continue.

In general,

\[ E \text{ meets an } n\text{-port agent} \quad\Longrightarrow\quad n \text{ erasers continue on its auxiliary branches.} \]

This makes erasure local. The net does not need to search globally for every part of an unused argument. The erasure signal propagates through the graph by local interactions.

3.3 Replicators

A replicator \(R\) has one principal port and any natural number of auxiliary ports. Its arity is the number of auxiliary ports.

The principal connection receives a shared value. The auxiliary connections lead to the uses of that value.

A replicator carries:

  • an integer level \(\ell_R\);
  • one integer delta \(d_i\) for each auxiliary port \(i\).

The level names a sharing context. A delta is a relative level adjustment attached to one specific exit:

\[ \text{new level of a replica} = \text{old level} + \text{delta of the exit port}. \]

A delta is not:

  • a copy count;
  • a source-language variable value;
  • a runtime closure environment.

The replicator’s arity already determines how many explicit consumer connections it has. If the arity is \(4\), there are four auxiliary exits. The deltas do not say “make four copies.” They say how the sharing context changes at each exit.

A one-port replicator with delta \(0\) is equivalent to a wire. It neither branches nor changes level. Canonical construction omits it.

3.4 The four λ-fragments

The agent vocabulary corresponds to four disciplines for bound-variable use.

λ-fragment Bound-variable rule Δ-Net subsystem Permitted agents
\(\lambda L\) Exactly once \(\Delta L\) Fan
\(\lambda A\) At most once \(\Delta A\) Fan, eraser
\(\lambda I\) At least once \(\Delta I\) Fan, replicator
\(\lambda K\) Any number of times \(\Delta K\) Fan, eraser, replicator

These names express four possibilities.

A linear binder uses its variable exactly once. It needs neither erasure nor duplication. Hence \(\Delta L\) uses fans only.

An affine binder uses its variable zero or one times. It may need erasure. Hence \(\Delta A\) adds erasers.

A relevant binder uses its variable at least once. It may need sharing. Hence \(\Delta I\) adds replicators.

A full binder uses its variable any number of times. It may need both erasure and sharing. Hence \(\Delta K\) uses all three agents.

The operational interpretation is:

  • fan pays for structural λ-term shape;
  • eraser pays for omission;
  • replicator pays for sharing.

4. Local interaction rules

An interaction rule applies when two principal ports meet. In Δ-Nets, such interactions fall into three broad families:

  1. annihilation;
  2. erasure;
  3. commutation.

These names describe what happens to the active pair.

4.1 Annihilation

Equal agents annihilate. Both agents disappear and corresponding auxiliary ports reconnect.

For fans, this is β-reduction in graph form. The application fan and abstraction fan meet at their principal ports. Annihilation reconnects:

\[ \text{application result} \leftrightarrow \text{abstraction body}, \]

\[ \text{application argument} \leftrightarrow \text{abstraction variable interface}. \]

This realizes substitution structurally rather than by textual copying.

The correspondence of ports is by identity, not by visible geometric position. Suppose a fan is drawn upside down. Its first auxiliary port may appear on the right rather than on the left. It is still the first auxiliary port. Therefore wires may cross in a drawing while still preserving the correct port-index matching.

Example: one linear β-step

Consider:

\[ (\lambda x.x)(\lambda y.y) \;\longrightarrow_\beta\; \lambda y.y. \]

The displayed term is linear. The variable \(x\) occurs exactly once in the body of \(\lambda x.x\), and \(y\) occurs exactly once in the body of \(\lambda y.y\). Its \(\Delta L\) encoding therefore needs fans only.

The outer application is represented by an application fan. Its function connection leads to the abstraction fan for \(\lambda x.x\). These two fans meet at their principal ports. They form an active pair.

The abstraction \(\lambda x.x\) has its body port and variable port connected directly, because \(x\) has exactly one occurrence. When the application fan and abstraction fan annihilate, the application result is connected to the abstraction body, and the application argument is connected to the variable interface. Since the body and variable interface of \(\lambda x.x\) are already identified, the root becomes connected directly to the argument net. That argument net is the encoding of \(\lambda y.y\).

Thus one β-step corresponds to one fan annihilation.

For the linear subsystem, the stated correspondence is exact: if a \(\lambda L\) term normalizes in \(n\) β-steps, then its \(\Delta L\) encoding normalizes in \(n\) interactions in any interaction order.

4.2 Erasure

An erasure interaction occurs when an eraser meets a distinct agent.

Because \(E\) has no auxiliary ports, the other agent has no continuation through the eraser’s side. The interaction deletes the encountered structure and propagates erasers through its auxiliary outputs.

For a fan with two auxiliary ports:

Before:                  After:

      E                        E ── branch 1
      |                        E ── branch 2
      F
    /   \
 branch 1 branch 2

The fan disappears. Each branch that was attached to an auxiliary port receives an eraser.

This rule is the graph counterpart of an unused argument being discarded. It is local. The eraser does not need to inspect an entire argument before deletion begins. It pushes the deletion request through the structure it meets.

If an eraser meets an \(n\)-port replicator, the result has \(n\) erasers, one at each auxiliary branch. This follows the same principle:

\[ E \text{ meets an } n\text{-port agent} \quad\Longrightarrow\quad n \text{ erasers continue on its auxiliary branches.} \]

4.3 Commutation

A commutation interaction occurs when two distinct non-eraser agents meet. They do not annihilate. Instead, each passes through the other’s surrounding structure. Copies are generated according to arities.

The simplest important case is a fan meeting a replicator.

Suppose an \(m\)-port replicator meets a two-port fan.

  • The replicator is copied through the fan’s two auxiliary ports.
  • The fan is copied once for each replicator auxiliary port.
  • The resulting connections form an \(m\times 2\) indexed grid.

If the fan copies are indexed by replicator ports, and the replicator copies are indexed by fan ports, the reconnection is described by

\[ (F_i)_j \leftrightarrow (R^j)_i. \]

Here \(F_i\) denotes the copy of the fan associated with replicator auxiliary port \(i\), and \(R^j\) denotes the copy of the replicator associated with fan auxiliary port \(j\). The notation says that auxiliary port \(j\) of \(F_i\) connects to auxiliary port \(i\) of \(R^j\).

The indices determine the rule. A drawing may rotate one of the agents. The rule still follows port identities.

Commutation is the operation that moves sharing structure through term structure. It is the local mechanism by which a shared computation can be exposed to several consumer contexts without substituting text.

4.4 Replicator–replicator interaction

Replicators require a separate discussion because they carry levels and deltas.

Let two replicators meet at their principal ports.

There are two cases:

  1. they are equal;
  2. they have different levels.

Equal replicators

Formally, equal replicators must match in:

  1. level;
  2. arity;
  3. every port delta.

If equal replicators meet, they annihilate.

The interaction removes both replicators and reconnects equal-indexed auxiliary ports. No replicas are created.

For canonical nets produced by the λ-term translation, there is an important invariant: active replicators at the same level are already equal. In that restricted setting, comparing levels is sufficient. The invariant supplies equality of arity and port deltas.

For arbitrary hand-built nets, level equality is not sufficient. Two replicators may have the same level but different arities. They may also have the same level and arity but different deltas. Such replicators are not equal in the formal sense.

Thus there are two different statements.

  • In canonical translations satisfying the invariant, same-level active replicators may be treated as equal.
  • In arbitrary nets, equal levels alone do not prove equality.

Different levels

If two active replicators have different levels, they commute rather than annihilate.

Let \(R\) be the lower-level replicator, and let \(H\) be the higher-level replicator. Suppose \(R\) has auxiliary ports indexed by \(i\), with deltas \(d_i\). Suppose \(H\) has old level \(\ell_H\).

Then:

  • \(R\) produces one replica of \(H\) for every auxiliary port of \(R\);
  • \(H\) produces one exact copy of \(R\) for every auxiliary port of \(H\);
  • the copy of \(H\) that exits through \(R\)-port \(i\) receives the delta \(d_i\).

Thus the new level of that \(H\)-replica is

\[ \ell_{H_i}' = \ell_H + d_i. \]

The copies of \(R\) preserve \(R\)’s own level and deltas. This asymmetry is essential. The delta belongs to the exit of \(R\), so it modifies the higher-level replica that traverses that exit.

This is a use of the general replicator rule:

\[ \text{new level of a replica} = \text{old level} + \text{delta of the exit port}. \]

A delta can be negative, zero, or positive. Negative deltas lower the level. Positive deltas raise it. Zero deltas preserve it.

Worked calculation

Let:

\[ \ell_R = 2, \qquad \ell_H = 7. \]

Suppose \(R\) has two ports whose endpoints lie at levels \(2\) and \(5\). Then the deltas on those ports are computed relative to \(\ell_R=2\):

\[ d_A = 2 - 2 = 0, \]

\[ d_B = 5 - 2 = +3. \]

When \(H\) commutes through \(R\), one \(H\)-replica exits through port \(A\), and another exits through port \(B\). Their levels are

\[ \ell_{H_A}' = 7 + 0 = 7, \]

\[ \ell_{H_B}' = 7 + 3 = 10. \]

The port values are local instructions:

port A: use H's current level, unchanged
port B: add 3 to H's current level

The same exit rule applies to every higher-level replicator that later passes through that port. If a replica begins at level \(12\), then exit \(B\) produces level

\[ 12 + 3 = 15. \]

The delta \(+3\) is not the level \(5\) itself. It is the difference between the endpoint level and the replicator level. It can be reused locally because it is a relative instruction.

5. Compiling λ-terms into canonical nets

For each of the four λ-fragments, there is a bijection

\[ \varphi: \{\text{terms}\} \longleftrightarrow \{\text{canonical Δ-Nets}\}. \]

A bijection has two directions:

  • each source term maps to one canonical net;
  • each canonical net maps back to one source term.

The translation is inductive. One first translates the immediate subterms, then wires the translated fragments into a larger fragment.

A canonical net is a net in the standard term-like form generated by this translation. It is the form that the inverse translation \(\varphi^{-1}\) reads.

5.1 Fragment interfaces

Every translated fragment has a uniform interface.

Each translated fragment has:

  • one incoming result wire;
  • zero or more outgoing interface wires;
  • a single root for the whole closed net.

The incoming wire connects the fragment to its parent context. The outgoing interface wires expose free variables or bound-variable endpoints that must be connected by surrounding binders.

A free variable appears as a named interface node. It is not a rewriting agent. It has a name because the surrounding term has not supplied a binder for it.

A bound variable occurrence is different. It is represented by a wire endpoint. Later, that endpoint is connected to the structure of its owning binder. If there is exactly one occurrence, the connection is direct. If there are several occurrences, the connection is through a replicator. If there are no occurrences, the binder’s variable port is connected to an eraser in a subsystem where erasure is permitted.

The distinction is important.

  • Free variables survive at the boundary as names.
  • Bound variable occurrences do not become variable agents.
  • Sharing is represented by replicators, not by duplicating named variable nodes.

5.2 Variable-use cases for a binder

For a binder \(\lambda x.M\), there are three cases.

Occurrences of \(x\) in \(M\) Representation
0 Connect the variable port to an eraser, where permitted
1 Connect directly to the single occurrence
\(>1\) Connect to a replicator with one auxiliary port per occurrence

Examples:

\[ \lambda x.x \]

has one occurrence of \(x\). The binder’s variable port is wired directly to that occurrence.

\[ \lambda x.y \]

has no occurrence of \(x\). In \(\Delta A\) or \(\Delta K\), the binder’s variable port is wired to an eraser.

\[ \lambda x.x\,x \]

has two occurrences of \(x\). The binder’s variable port is wired to a two-port replicator. One auxiliary port serves the function occurrence. The other serves the argument occurrence.

The one-use case does not use a one-port replicator with delta \(0\). Such a replicator is equivalent to a wire, so the canonical representation omits it.

5.3 Application wiring

For an application \(M\,N\) at level \(\ell\):

  • \([M]_\ell\) connects to the principal port;
  • the parent or result wire uses the first auxiliary port;
  • \([N]_{\ell+1}\) uses the second auxiliary port.

Thus the application fan has the following port roles:

Port Role
Principal Function
First auxiliary Result or parent
Second auxiliary Argument

The level convention is also part of the application rule. The function subterm remains at level \(\ell\). The argument subterm is placed at level \(\ell+1\).

This wiring ensures that if the function subterm is an abstraction, the application fan and abstraction fan meet at their principal ports. Therefore a β-redex becomes an active pair.

5.4 Abstraction wiring

For an abstraction \(\lambda x.M\) at level \(\ell\):

  • the body \(M\) remains at level \(\ell\);
  • the binder’s replicator \(R_x\), if needed, is placed at level \(\ell+1\);
  • the abstraction’s first auxiliary port leads to the body;
  • its second auxiliary port leads to the bound-variable structure.

Thus the abstraction fan has the following port roles:

Port Role
Principal Parent
First auxiliary Body
Second auxiliary Bound-variable connection

The body remains at the same level as the abstraction. This is a central convention. Levels do not count λ-binders. They count application-argument edges, as described below.

If \(x\) occurs once, the bound-variable connection is a direct wire to the occurrence. If \(x\) occurs several times, it goes to \(R_x\). If \(x\) occurs zero times and erasure is permitted, it goes to \(E\).

6. Levels and deltas

Levels are static annotations computed from the written λ-term. They are not runtime environments. They are not closure contents. They are not values of source variables.

The whole term starts at level \(0\):

\[ \operatorname{level}(T)=0. \]

The rules for computing levels are recursive.

6.1 Level assignment

For abstraction:

\[ \operatorname{level}(\lambda x.M)=\ell \quad\Longrightarrow\quad \operatorname{level}(M)=\ell. \]

For application:

\[ \operatorname{level}(M\,N)=\ell \quad\Longrightarrow\quad \operatorname{level}(M)=\ell, \qquad \operatorname{level}(N)=\ell+1. \]

Thus a node’s level is the number of application-argument edges encountered on the route from the term root to that node.

Equivalently:

  • entering the body of an abstraction does not change level;
  • entering the function part of an application does not change level;
  • entering the argument part of an application adds one.

This definition is syntactic. It is computed before reduction from the structure of the term being translated.

6.2 Delta assignment

Suppose a binder \(\lambda x.M\) is at level \(\ell\). If \(x\) has several occurrences, the binder’s replicator \(R_x\) is placed at level

\[ \ell_R = \ell+1. \]

Let \(x_i\) be an occurrence of \(x\) reached at level \(\ell_i\). The delta on the corresponding auxiliary port is

\[ d_i = \ell_i - \ell_R. \]

This is the basic formula. It says that each port stores the occurrence level relative to the replicator level.

A delta is therefore a local difference. It is not an absolute position. If a later replicator passes through that port, the port adds the same difference to the later replicator’s current level.

6.3 Example: \(\lambda x.x\,x\)

Consider

\[ \lambda x.x\,x. \]

Write the body as an application:

\[ x_0\,x_1. \]

Start at level \(0\). The abstraction body remains at level \(0\). The body application is therefore at level \(0\).

By the application rule:

  • the function occurrence \(x_0\) has level \(0\);
  • the argument occurrence \(x_1\) has level \(1\).

The binder’s replicator is at level

\[ \ell_R = 0+1 = 1. \]

Hence the port deltas are

\[ d_0 = 0-1=-1, \]

\[ d_1 = 1-1=0. \]

Thus the replicator has delta vector

\[ \langle -1,0\rangle. \]

The vector has two entries because the replicator has two auxiliary ports. The number of entries records the number of consumer connections. The entries themselves record relative context.

6.4 Example: \(\lambda x.\,x\,(g\,x)\)

Write the term with explicit occurrence labels:

\[ \lambda x.\bigl(x_0\;(g\;x_1)\bigr). \]

Start at level \(0\).

  • The abstraction body remains at level \(0\).
  • In the outer application, function occurrence \(x_0\) has level \(0\).
  • The argument \(g\,x_1\) has level \(1\).
  • Inside \(g\,x_1\), \(g\) remains at level \(1\), while \(x_1\) has level \(2\).

The binder replicator is at:

\[ \ell_{R_x}=0+1=1. \]

Therefore:

\[ d_0=0-1=-1, \qquad d_1=2-1=+1. \]

So the delta vector is:

\[ \langle -1,+1\rangle. \]

The first occurrence lies one level below the replicator level. The second lies one level above it. The replicator records both facts locally.

6.5 Example: deeper right nesting

Consider:

\[ \lambda x.\,x\bigl(x\bigl(x\,x\bigr)\bigr). \]

Parenthesize the body as

\[ x_0\bigl(x_1\bigl(x_2\,x_3\bigr)\bigr). \]

Each successive right-hand subterm lies in the argument position of the application above it. Each such move adds one level.

The four occurrences lie at levels:

\[ 0,\;1,\;2,\;3. \]

The binder replicator is at level \(1\), so:

\[ \langle d_0,d_1,d_2,d_3\rangle = \langle 0-1,\;1-1,\;2-1,\;3-1\rangle = \langle -1,0,+1,+2\rangle. \]

Applying this abstraction to \(N\) yields:

\[ (\lambda x.\,x(x(x\,x)))\,N \;\longrightarrow_\beta\; N(N(N\,N)). \]

The four replicator ports represent four consumers. The delta vector does not say “make four copies”; the arity already says that. Instead, it records the relative sharing context of each consumer.

The following table makes the calculation explicit.

Occurrence Position Endpoint level Stored delta
\(x_0\) Function of the outer application \(0\) \(0-1=-1\)
\(x_1\) Function inside the first argument \(1\) \(1-1=0\)
\(x_2\) Function inside the second argument \(2\) \(2-1=+1\)
\(x_3\) Argument of the deepest application \(3\) \(3-1=+2\)

6.6 Why levels are not closure environments

A runtime closure stores code together with an environment for free variables. A Δ-Net level is not such an environment.

For example, in

\[ \lambda x.\lambda y.x, \]

the occurrence of \(x\) lies inside two abstractions if one counts binders. But by the level rules, entering an abstraction body does not change level. Starting at level \(0\), the occurrence of \(x\) is still at level \(0\).

By contrast, in

\[ \lambda x.f\,(g\,x), \]

the occurrence of \(x\) in \(g\,x\) is at level \(2\). The reason is not that it lies under two λ-binders. It lies in the argument of the outer application, and then in the argument of the inner application.

Levels track argument nesting for sharing contexts. They do not track lexical depth in the ordinary closure sense.

7. Reading β-reduction in the net

The translation is designed so that a β-redex becomes a principal-port active pair.

Consider a source redex:

\[ (\lambda x.M)\,N. \]

The outer application is translated as an application fan. Its principal port connects to the translation of the function \(\lambda x.M\). The abstraction is translated as an abstraction fan whose principal port is its parent connection. Thus the application fan and abstraction fan meet principal-to-principal.

Their annihilation performs the structural part of substitution.

The application result is connected to the abstraction body:

\[ \text{application result} \leftrightarrow \text{abstraction body}. \]

The application argument is connected to the abstraction variable interface:

\[ \text{application argument} \leftrightarrow \text{abstraction variable interface}. \]

What happens next depends on the use pattern of \(x\) in \(M\).

7.1 The linear case

If \(x\) occurs once, the variable interface is already wired directly to the occurrence. Connecting \(N\) to the variable interface connects \(N\) to that one occurrence.

This matches ordinary substitution without copying.

For

\[ (\lambda x.x)(\lambda y.y) \;\longrightarrow_\beta\; \lambda y.y, \]

one fan annihilation suffices.

7.2 The erasure case

If \(x\) occurs zero times, the variable interface is wired to an eraser. When the argument \(N\) is connected to that interface, the eraser propagates into the net for \(N\). The argument is disposed of by local erasure interactions.

This matches

\[ (\lambda x.t)\,u \;\longrightarrow_\beta\; t \]

when \(x\) is absent from \(t\).

The graph may contain disconnected garbage after erasure. That issue is handled by canonicalization, discussed below.

7.3 The sharing case

If \(x\) occurs more than once, the variable interface is wired to a replicator. The argument \(N\) is connected to the principal port of that replicator. The auxiliary ports lead to the occurrences.

This records that one supplied argument has several consumers. The net need not immediately copy the entire argument syntax. Instead, sharing is represented as graph structure. Later commutations move the replicator through surrounding agents as needed.

For

\[ (\lambda x.x\,x)\,u \;\longrightarrow_\beta\; u\,u, \]

the net version connects \(u\) to a two-port replicator. The two consumer ports correspond to the two occurrences. If \(u\) contains work, that work can remain shared until interactions force structure to be exposed.

8. Canonical nets and proper nets

The local interaction core is not the entire algorithm. Two classes of nets must be distinguished.

A canonical net is the standard term-like form generated by \(\varphi\), the term-to-net translation. It is the shape that the inverse translation \(\varphi^{-1}\) knows how to read.

A proper net is any net reachable from a canonical net through zero or more core Δ-interactions.

Thus:

\[ \text{canonical} \subseteq \text{proper}. \]

Every canonical net is proper. A proper net need not be canonical.

Core interactions may preserve computational meaning while leaving the net temporarily noncanonical. For example, commutations can create intermediate arrangements of replicators. Erasure can leave unreachable material. These states are part of computation. They are not necessarily valid final read-back forms.

Canonicalization restores the special canonical shape. It is not itself necessarily a principal-port interaction. It may inspect or reorganize structure in a way that is outside the local active-pair rules.

This distinction is essential.

  • Core interactions perform local computation.
  • Canonicalization restores a readable standard form.
  • Read-back by \(\varphi^{-1}\) applies to a normal canonical net, not to an arbitrary proper net.

8.1 Erasure canonicalization

In \(\Delta A\) and \(\Delta K\), erasure can leave disconnected subnets. A disconnected subnet may no longer be reachable from the root. It represents garbage.

The prescribed cleanup is a root-reachability sweep:

  1. begin at the distinguished root;
  2. follow parent–child wiring and mark reachable material;
  3. delete unmarked material;
  4. terminate exposed surviving connections with erasers where required.

This is a global cleanup pass. It is not a local active-pair rewrite.

The word “global” here has a precise meaning. The procedure depends on reachability from the root. Reachability cannot be decided by inspecting one active pair. One must traverse a portion of the graph.

The sweep may run at the end of reduction or earlier to control memory use. Early sweeping is useful after applying abstractions that ignore their arguments, since such applications can create large unused subnets.

There is a time-space trade-off.

  • Sweeping often may reduce memory.
  • Sweeping rarely may reduce cleanup overhead.
  • The correct choice for an implementation depends on graph size, sharing, and memory pressure.

8.2 Replicator merging

In \(\Delta I\) and \(\Delta K\), interactions can create trees consisting only of replicators. Some consecutive replicators represent redundant sharing structure. A merge rule can collapse them when a local condition proves that the later replicator is unpaired.

A consecutive pair of replicators is a pair in which a port of one is directly connected to a port of the other, with no intervening agent.

An unpaired replicator is one that has no active partner of the kind that would cause its annihilation before the relevant earlier structure is resolved. The formal definition belongs to the net invariant, but the operational test used here is the following.

Suppose consecutive replicators \(A\) and \(B\) are connected through a port of delta \(d\). The source gives the test:

\[ 0 \leq \ell_B-\ell_A \leq d. \]

Under the stated interpretation, this proves that \(B\) is unpaired: it cannot interact before \(A\) would be annihilated, and \(A\) is itself unpaired.

The inequality is therefore a safety condition, not merely an optimization heuristic.

After merging:

  • external endpoint levels remain unchanged;
  • the surviving replicator retains its level;
  • deltas are recomputed relative to that level.

For example, suppose the surviving level is \(2\), and the external endpoints are at levels \(2\), \(3\), and \(6\). Then the new deltas are:

\[ \langle 2-2,\;3-2,\;6-2\rangle = \langle 0,+1,+4\rangle. \]

The merge has not changed the levels of the external endpoints. It has changed the internal representation so that one replicator records the same relative information.

8.3 Replicator decay in \(\Delta K\)

The full system \(\Delta K\) contains both erasers and replicators. This creates one more cleanup case.

An unpaired replicator may have auxiliary ports that lead directly to erasers. Such ports represent consumers that have been erased. They can be removed.

This cleanup is called replicator decay. It removes auxiliary ports of unpaired replicators that lead directly to erasers.

If the remaining replicator has one auxiliary port with delta \(0\), it collapses to a wire. It no longer represents either sharing or a level transition.

This agrees with the canonical convention: a one-port zero-delta replicator is not represented as an agent.

9. Operational discipline

The local core has perfect confluence. But the nonlinear systems require more than the local core.

The reason is that canonicalization can inspect or rewrite structure outside principal-to-principal active pairs. Therefore the local one-step diamond property does not by itself specify when cleanup should occur.

For the nonlinear systems \(\Delta A\), \(\Delta I\), and \(\Delta K\), the operational discipline uses a leftmost-outermost schedule.

A reducible pattern is outermost if it is not contained within another reducible pattern. Among outermost reducible patterns, the leftmost one is chosen according to the term-like reading of the canonical net.

The schedule is:

  1. choose an outermost reducible pattern;
  2. among those, choose the leftmost one in the term-like reading of the net.

This is the same priority idea as normal-order reduction in λ-calculus, adapted to the net representation and its cleanup operations.

9.1 Why outermost first

Outermost reduction delays work inside an argument until the surrounding application has established that the argument is needed.

For example,

\[ (\lambda x.y)\;((\lambda z.z)\,w) \]

should reduce the outer redex first. Entering the argument first is wasted because the argument is erased.

In the net, the same idea is enforced by scheduling. The outer interaction connects the argument to an eraser. Cleanup can then remove unused material before internal redexes in that argument are reduced.

9.2 Why leftmost

When several outermost redexes are available, the leftmost convention gives a deterministic sequential priority. This is important for the nonlinear systems because cleanup and merging interact with future commutations.

The schedule allows cleanup and merging to occur before later commutations spread unnecessary structure. In particular:

  • erasure cleanup should remove garbage before it is duplicated or traversed;
  • replicator merging should collapse redundant sharing trees before further commutations enlarge them;
  • decay should remove eraser-bound ports before they participate in irrelevant structure.

The leftmost-outermost schedule is not a rejection of parallelism. It is a priority discipline for preserving the desired optimality behavior.

9.3 Limited safe parallelism

A reducible pair may run early if it can be shown that it will later reach the leftmost-outermost position unchanged.

This is a conditional permission. It is not a general license to reduce any currently disjoint pair early.

The condition has two parts.

  1. The pair must eventually become the leftmost-outermost reducible pattern.
  2. It must remain unchanged until then.

If both hold, performing the interaction early does not disturb the scheduled computation. This preserves some parallelism while keeping the scheduling invariants.

9.4 Local confluence versus global discipline

There is no contradiction between local perfect confluence and a global schedule.

The local core says that active-pair interactions commute. It speaks about principal-to-principal rules.

The full nonlinear algorithm also contains:

  • reachability sweeps;
  • replicator merging;
  • decay;
  • canonicalization;
  • priority choices.

These are not all principal-port interactions. They need their own discipline.

Thus the statement “the core is locally confluent” is different from the statement “the full nonlinear reduction algorithm may ignore scheduling.” The latter is false.

10. The whole algorithm

The intended pipeline is:

\[ t \;\xrightarrow{\varphi}\; \varphi(t) \;\xrightarrow{\Delta^\ast}\; \text{proper net} \;\xrightarrow{\Omega}\; \text{normal canonical net} \;\xrightarrow{\varphi^{-1}}\; t'. \]

Here:

  • \(t\) is the source λ-term;
  • \(\varphi(t)\) is its canonical Δ-Net;
  • \(\Delta^\ast\) denotes zero or more core interactions;
  • \(\Omega\) denotes the subsystem’s full operational discipline: interactions, schedule, and canonicalizations;
  • \(t'\) is the read-back λ-term in normal form.

The stages must remain distinct.

  1. Encoding: \(\varphi\) constructs a canonical net.
  2. Core reduction: local interactions may enter the larger space of proper nets.
  3. Canonicalization and scheduling: \(\Omega\) returns the net to a canonical normal form.
  4. Read-back: \(\varphi^{-1}\) applies only once the net is normal and canonical.

A proper net should not be mistaken for a final term representation merely because it is reachable from a canonical one.

10.1 Normality and canonicity are different

A net can fail to be normal because it still contains active pairs or reducible cleanup patterns.

A net can fail to be canonical because its structure is not in the standard term-like form expected by \(\varphi^{-1}\).

These are different failures.

  • A non-normal canonical net still looks like a term translation, but it can reduce.
  • A normal proper net may have no core active pairs but still not be readable as a canonical term.
  • A final read-back requires both properties: normal and canonical.

10.2 Subsystem-specific behavior

The four subsystems differ because they admit different agents.

System Extra concern Prescribed response
\(\Delta L\) None beyond fan annihilation Any interaction order; perfect confluence
\(\Delta A\) Disconnected erased subnets Leftmost-outermost plus erasure canonicalization
\(\Delta I\) Replicator trees and early copying Leftmost-outermost plus merging/canonicalization
\(\Delta K\) Both garbage and sharing structure Leftmost-outermost plus erasure, merging, and decay

In \(\Delta L\), every binder is used exactly once. There are no erasers and no replicators. Fan annihilation is the only computational interaction. Every proper \(\Delta L\) net remains canonical. If a \(\lambda L\) term normalizes in \(n\) β-reductions, its \(\Delta L\) encoding normalizes in \(n\) interactions, independently of the order of interactions.

In \(\Delta A\), unused arguments can generate garbage. Erasure canonicalization is needed.

In \(\Delta I\), sharing can generate replicator structure that must be merged or canonicalized.

In \(\Delta K\), both erasure and sharing are present. The system needs erasure canonicalization, replicator merging, and decay.

11. Confluence, Church–Rosser confluence, and optimality

Several agreement properties must be kept separate.

11.1 One-step diamond property

The one-step diamond property concerns immediate local competition:

\[ N\to N_1,\quad N\to N_2 \quad\Longrightarrow\quad N_1\to M,\quad N_2\to M. \]

Every arrow is one interaction step.

This property is strong. It says that if two different active pairs are chosen from the same net, the two possible one-step results can be joined after one additional step on each side.

In interaction nets, the reason is locality: distinct active pairs share no agent.

11.2 Church–Rosser confluence

Church–Rosser confluence is broader. It concerns finite reduction paths, not just one-step divergences.

A reduction relation is Church–Rosser confluent if whenever a net reduces along two finite paths to two results, those results can be extended along further paths to a common net.

It does not require the two paths to agree after one additional step. The joining paths may have many steps.

Thus one-step diamond and Church–Rosser confluence are not the same statement.

The nonlinear systems require the full construction: local interactions, canonicalization, and the global schedule. Their confluence and optimality properties are not properties of the bare three-agent interaction core alone.

11.3 Optimality as a formal property

The word optimal has a technical meaning in this setting. It is not merely a claim that an implementation is fast. The intended optimality is that no necessary shared computation is duplicated, and no computation that is known to be erased is performed.

The construction separates three objectives.

No discarded work

Leftmost-outermost reduction aims to avoid evaluating a subnet that will later be erased. Root-reachability cleanup then removes leftover garbage.

No repeated work

Replicators place shared use inside the graph. Multiple consumers can remain connected to one evolving computation rather than forcing independent textual substitutions.

Local parallelism

Perfect confluence allows disjoint active pairs to choose and apply local rules independently.

These goals interact. Sharing without cleanup may keep too much structure. Cleanup without scheduling may occur too late. Parallelism without certification may reduce work that the scheduled computation would avoid. The full discipline coordinates the pieces.

12. Feasibility, limitations, and implementation obligations

Δ-Nets move scope-sensitive sharing information from separate delimiter-agent machinery into the local metadata of variable-arity replicators.

That design has clear attractions:

  • sharing is visible in the graph;
  • local rules operate on small neighborhoods;
  • deltas provide per-port context adjustment;
  • the core retains a strong local confluence property;
  • variable arity can represent many consumers without encoding every sharing point as a binary structure.

Several limitations matter.

12.1 Locality is not the entire story

Core interactions are local, but erasure canonicalization is global because it depends on reachability from the root. The nonlinear algorithm therefore is not purely local in the strongest possible sense.

A root-reachability sweep must inspect the graph beyond one active pair. It marks reachable material, deletes unreachable material, and inserts erasers at exposed surviving connections. This is a graph traversal, not a principal-port interaction.

12.2 Equality shortcuts depend on translation invariants

For a well-formed canonical λ-term translation, same-level active replicators may be treated as equal. The translation invariant supplies matching arity and deltas.

Arbitrary hand-built nets do not inherit this guarantee. They require full comparison of:

  1. levels;
  2. arities;
  3. corresponding port deltas.

An implementation that compares only levels outside the invariant may perform invalid annihilations.

12.3 Deltas require disciplined interpretation

A delta is a relative context displacement. It is computed by

\[ d_i = \ell_i - \ell_R. \]

It is used by

\[ \text{new level of a replica} = \text{old level} + \text{delta of the exit port}. \]

It is not a copy count, a variable value, a pointer into an environment, or an arbitrary label. Treating it as any of these would obscure the invariant it maintains.

12.4 Canonicalization must be represented explicitly

A practical implementation must decide how canonical forms are represented. It must know which nets are directly readable by \(\varphi^{-1}\), which nets are merely proper, and which cleanup rules restore canonicity.

This includes:

  • representation of the root;
  • representation of free-variable interface nodes;
  • orientation or parent–child information;
  • port identities independent of drawing position;
  • detection of one-port zero-delta replicators;
  • detection of eraser-bound auxiliary ports;
  • detection of consecutive replicators eligible for merging.

12.5 Scheduling is part of the nonlinear algorithm

For \(\Delta A\), \(\Delta I\), and \(\Delta K\), the leftmost-outermost discipline is not optional background. It is part of the operational construction.

A parallel implementation must therefore certify early interactions. It is not enough to find disjoint active pairs. One must know that a pair reduced early will later reach the leftmost-outermost position unchanged, or otherwise restrict reduction to the scheduled choice.

12.6 Space and time trade-offs remain

Early erasure sweeping can save memory, especially after applications of abstractions that ignore their arguments. But sweeping itself costs time. Delaying sweeping can reduce traversal overhead but may retain garbage longer.

Likewise, eager replicator merging can prevent later blow-up of sharing structure, but detecting merge conditions and maintaining levels has a cost.

The mathematical construction specifies correctness conditions. An implementation must still choose data structures and scheduling policies that realize them efficiently.

12.7 “Optimal” is a theorem-level property

The optimality and confluence statements depend on definitions, invariants, schedules, and canonicalization procedures. They are not consequences of using three agent names alone.

A practical implementation must establish:

  • how canonical forms are represented;
  • how levels and deltas are stored and compared;
  • when reachability sweeps occur;
  • how early parallel interactions are certified safe;
  • whether the implementation preserves the translation invariants.

13. Worked examples

13.1 Erasing an unused argument

Consider

\[ (\lambda x.y)\;((\lambda z.z)\,w). \]

The source-level β-step is

\[ (\lambda x.y)\;((\lambda z.z)\,w) \;\longrightarrow_\beta\; y. \]

In a net for an erasure-capable subsystem, the abstraction \(\lambda x.y\) has its bound-variable port connected to an eraser. The outer application fan meets the abstraction fan. Fan annihilation connects the argument net to the eraser. The eraser then propagates through the argument net.

If the schedule is leftmost-outermost, the inner redex \((\lambda z.z)\,w\) is not reduced before the outer application has exposed the erasure. The computation inside the argument is avoided.

The remaining detached or unreachable structure is removed by erasure canonicalization.

13.2 Sharing a duplicated argument

Consider

\[ (\lambda x.x\,x)\,u. \]

The source-level β-step is

\[ (\lambda x.x\,x)\,u \;\longrightarrow_\beta\; u\,u. \]

The body \(x\,x\) has two occurrences of \(x\). The abstraction’s variable port therefore connects to a two-port replicator. The argument \(u\) is connected to the principal port of that replicator after fan annihilation.

If \(u\) contains a redex, the net does not need to make two independent textual copies immediately. The single argument graph is shared through the replicator. Later interactions expose the needed structure to the two consumer positions.

At level \(0\), the abstraction’s replicator has level \(1\). The function occurrence has level \(0\), and the argument occurrence has level \(1\). Hence the deltas are

\[ \langle -1,0\rangle. \]

These deltas describe where the two uses sit relative to the replicator.

13.3 A mixed sharing-context example

Consider

\[ \lambda x.\,x\,(g\,x). \]

The two occurrences of \(x\) are not at the same level. The first occurrence is the function of the outer application. The second is the argument of the inner application \(g\,x\), which itself is the argument of the outer application.

The level calculation is:

\[ \operatorname{level}(\lambda x.\,x\,(g\,x))=0. \]

The body remains at level \(0\). For the outer application,

\[ \operatorname{level}(x_0)=0, \qquad \operatorname{level}(g\,x_1)=1. \]

For the inner application,

\[ \operatorname{level}(g)=1, \qquad \operatorname{level}(x_1)=2. \]

The replicator for \(x\) is at level \(1\). Therefore

\[ d_0=0-1=-1, \qquad d_1=2-1=+1. \]

The replicator has delta vector

\[ \langle -1,+1\rangle. \]

A later higher-level replicator passing through the first port lowers its level by one. Passing through the second port raises its level by one. This is how the net preserves the different consumer contexts.

13.4 A four-use example

Consider

\[ (\lambda x.\,x(x(x\,x)))\,N. \]

At the source level,

\[ (\lambda x.\,x(x(x\,x)))\,N \;\longrightarrow_\beta\; N(N(N\,N)). \]

The abstraction body has four occurrences of \(x\). Its replicator has four auxiliary ports. At level \(0\), the occurrence levels are

\[ 0,\;1,\;2,\;3. \]

The replicator level is \(1\). Thus

\[ \langle d_0,d_1,d_2,d_3\rangle = \langle 0-1,\;1-1,\;2-1,\;3-1\rangle = \langle -1,0,+1,+2\rangle. \]

The four consumers are represented by the arity. The relative positions of the consumers are represented by the deltas.

14. Summary of definitions

A λ-term is generated by

\[ t ::= x \mid \lambda x.t \mid t\,u. \]

A β-redex is a term of the form

\[ (\lambda x.t)\,u. \]

Its β-reduction is

\[ (\lambda x.t)\,u \;\longrightarrow_\beta\; t[x:=u]. \]

A normal form is a term or net with no remaining reducible pattern. A term or net is normalizing if some reduction sequence reaches a normal form.

An agent is a node in an interaction net. It has one principal port and zero or more auxiliary ports.

An active pair is two agents connected at their principal ports.

An interaction step is one local rewrite of an active pair.

A fan is a two-auxiliary-port agent used for application and abstraction structure.

An eraser is a zero-auxiliary-port agent used for non-use.

A replicator is a variable-arity agent used for sharing. It has a level and one delta for each auxiliary port.

A level is a static integer assigned by walking the syntax tree:

\[ \operatorname{level}(T)=0, \]

\[ \operatorname{level}(\lambda x.M)=\ell \quad\Longrightarrow\quad \operatorname{level}(M)=\ell, \]

\[ \operatorname{level}(M\,N)=\ell \quad\Longrightarrow\quad \operatorname{level}(M)=\ell, \qquad \operatorname{level}(N)=\ell+1. \]

A delta on a replicator port is

\[ d_i = \ell_i - \ell_R, \]

where \(\ell_i\) is the level of the connected occurrence endpoint and \(\ell_R\) is the level of the replicator.

A canonical net is a net produced by the translation \(\varphi\).

A proper net is a net reachable from a canonical net through zero or more core Δ-interactions.

Thus:

\[ \text{canonical} \subseteq \text{proper}. \]

Canonicalization is cleanup that restores proper nets to canonical form.

Perfect confluence is the one-step diamond property:

\[ N \longrightarrow N_1, \qquad N \longrightarrow N_2 \]

implies that there is an \(M\) such that

\[ N_1 \longrightarrow M, \qquad N_2 \longrightarrow M. \]

Church–Rosser confluence is the broader property that two finite reduction paths from the same starting point can be extended to a common result.

Leftmost-outermost reduction chooses an outermost reducible pattern, then chooses the leftmost one among those.

15. Exercises

Exercise 1: Classify variable use

Classify each term as linear, affine, relevant, or full with respect to the displayed binder.

  1. \(\lambda x.x\)
  2. \(\lambda x.y\)
  3. \(\lambda x.x\,x\)
  4. \(\lambda x.x(x\,x)\)

Answer.

  1. Linear: one occurrence.
  2. Affine: zero occurrences.
  3. Relevant: at least one occurrence, with repetition.
  4. Full: unrestricted use; this term happens to use \(x\) three times.

Exercise 2: Compute deltas

For:

\[ \lambda x.\,x\,(h\,(k\,x)), \]

find the levels of the two occurrences of \(x\), then compute their deltas.

Hint. The binder is at level \(0\), so its replicator is at level \(1\). Each application argument edge adds one level.

Answer.

The first occurrence is the function of the outer application. Therefore it has level \(0\).

The second occurrence lies inside the argument of the outer application:

\[ h\,(k\,x). \]

That argument has level \(1\). Inside it, \(h\) remains at level \(1\), and the argument \(k\,x\) has level \(2\). Inside \(k\,x\), \(k\) remains at level \(2\), and the occurrence of \(x\) has level \(3\).

With the level rules stated in this chapter, the second occurrence is therefore at level \(3\). If one treats \(h\,(k\,x)\) as contributing only the outer argument edge and the argument edge into \(x\), omitting the intermediate argument edge into \(k\,x\), one obtains level \(2\). The fully parenthesized syntax gives the precise calculation:

\[ x\,(h\,(k\,x)). \]

The path to the second \(x\) crosses three argument edges:

  1. into \(h\,(k\,x)\);
  2. into \(k\,x\);
  3. into \(x\).

Thus the occurrence levels are

\[ 0,\;3. \]

The binder’s replicator level is

\[ \ell_R=1. \]

Hence

\[ d_0=0-1=-1, \]

\[ d_1=3-1=+2. \]

So the delta vector is

\[ \langle -1,+2\rangle. \]

Exercise 3: Erasure propagation

An eraser meets a replicator with four auxiliary ports. How many erasers continue after the interaction?

Answer. Four: one for each auxiliary branch.

Exercise 4: Replicator commutation

Let \(R\) have level \(3\) and port deltas \(\langle -2,0,+4\rangle\). A higher-level replicator \(H\) at level \(8\) commutes through \(R\). What are the levels of the three \(H\)-replicas?

Answer.

Each \(H\)-replica adds the delta of the \(R\)-port through which it exits:

\[ 8+(-2)=6,\qquad 8+0=8,\qquad 8+4=12. \]

So the levels are:

\[ \langle 6,8,12\rangle. \]

Exercise 5: One-port replicators

Why does canonical construction omit a one-port replicator with delta \(0\)?

Answer.

A one-port replicator has only one consumer. Therefore it does not express sharing. If its only delta is \(0\), it also does not express a level shift. It is equivalent to a wire. Canonical construction represents it as a wire.

Exercise 6: Fan annihilation

In a β-redex, which application-fan port reconnects to the abstraction body, and which reconnects to the abstraction variable interface?

Answer.

The application fan’s first auxiliary port is the result or parent connection. It reconnects to the abstraction fan’s first auxiliary port, the body.

The application fan’s second auxiliary port is the argument connection. It reconnects to the abstraction fan’s second auxiliary port, the bound-variable interface.

Thus:

\[ \text{application result} \leftrightarrow \text{abstraction body}, \]

\[ \text{application argument} \leftrightarrow \text{abstraction variable interface}. \]

Exercise 7: Replicator merging

Suppose consecutive replicators \(A\) and \(B\) are connected through a port of delta \(d=5\). Let

\[ \ell_A=4, \qquad \ell_B=7. \]

Does the local merge test allow the conclusion that \(B\) is unpaired?

Answer.

Compute

\[ \ell_B-\ell_A = 7-4=3. \]

The test is

\[ 0 \leq \ell_B-\ell_A \leq d. \]

Here

\[ 0 \leq 3 \leq 5. \]

So the test succeeds. Under the stated interpretation, \(B\) is known to be unpaired, and the consecutive replicators may be merged if the other hypotheses of the merge rule hold.

Exercise 8: Endpoint levels after merging

A merge leaves a surviving replicator at level \(2\). Its external endpoints are at levels \(2\), \(3\), and \(6\). Compute the new deltas.

Answer.

Deltas are endpoint levels minus the surviving replicator level:

\[ \langle 2-2,\;3-2,\;6-2\rangle = \langle 0,+1,+4\rangle. \]

Conclusion

Δ-Nets recast λ-reduction as graph rewriting with explicit structural treatment of variable use.

  • Fans encode λ-term structure.
  • Erasers encode omission.
  • Variable-arity replicators encode shared use.
  • Levels and per-port deltas carry relative sharing-context information.
  • Principal-port interactions provide local, perfectly confluent core dynamics.
  • Canonicalization and leftmost-outermost scheduling provide the additional discipline needed for the nonlinear subsystems.

The central construction separates substitution into local graph operations. If a bound variable is unused, erasure is explicit. If a bound variable has several occurrences, sharing is explicit. If sharing crosses different consumer contexts, levels and deltas record the required relative adjustments.

Thus the graph does not merely simulate textual substitution. It represents the operational facts that textual substitution hides: which arguments are discarded, which arguments are shared, and which local contexts each shared use inhabits.
